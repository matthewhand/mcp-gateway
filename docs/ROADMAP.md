## Backlog

### Security
- ◑ **P1 — Secret rotation story.** *(runbook done; env-ref hardening pending)* `servers.json` holds upstream keys in cleartext and the bearer/grok secrets sit in nginx + `~/.config`. No rotation procedure or expiry. → Document a rotation runbook; consider sourcing keys from env/`${VAR}` (proxy supports it) instead of inline literals so `servers.json` itself carries no secrets.
- **P2 — Single OAuth client.** One static `client_id=grok` + long-lived secret for all clients; no per-client scoping or revocation. → Per-client credentials + a revoke list in `oauth-server.py`.
- **P2 — Static bearer never expires.** The glama `/mcp` bearer is permanent. → Rotation schedule or move glama fully to OAuth.
- **P3 — fail2ban ISP whitelist is broad** (`121.44.0.0/15`). Accepted trade-off; revisit if abused.

### Reliability / resilience
- ✅ ~~P1 — Container memory limits.~~ **DONE** netbox(×6)+zep+wp on a halved-RAM box already OOM-killed netbox once. No `mem_limit`/`deploy.resources`. → Add per-stack memory caps + swap accounting so one stack can't starve the gateway.
- ✅ ~~P2 — No real watchdog.~~ **DONE** Health monitoring is a manual loop. → A small systemd timer running `status.sh` that restarts a dead `mcp-server@*` and alerts (PushNotification / log) on repeated failure.
- ✅ ~~P2 — netbox/getzep backend-container healthcheck~~ **DONE** watchdog now warns distinctly when `netbox-docker-netbox-1`/`zep-ce-zep-1` is down (bridge up but degraded), separate from a crash.

### Developer experience / workflow
- ✅ ~~P1 — `add-server` helper.~~ **DONE** Adding a server = hand-edit `servers.json` + guess auth env + restart + manually add an nginx `/oauth/ex/<name>` block. Error-prone. → `bin/add-server <name> <spec_url>` that appends to the manifest, scaffolds the nginx route, validates, and starts it.
- ✅ ~~P2 — Manifest validation.~~ **DONE** No schema check on `servers.json`; a typo silently breaks a bridge. → `bin/validate.sh` (JSON schema + port-collision + spec reachability).
- **P2 — Whitelist is prefix-deep & no blacklist.** Curating a lean toolset means hand-building mini-specs (asana, github). → Track engine `TOOL_BLACKLIST` (branch exists upstream) + exact-match whitelist mode.
- ✅ ~~P3 — One-command status~~ **DONE** (status.sh: core+servers+containers+TLS+disk+mem+watchdog+fail2ban).

### Observability
- ✅ ~~P2 — Status dashboard~~ **DONE** `bin/dashboard.sh` → `status.html` (server grid, mem/disk, containers; regenerated by the watchdog every 5 min; badges + threshold colors critiqued & fixed).
- ✅ ~~P2 — Serve + enrich the dashboard~~ **DONE** live WebUI at `/` and `/status` (htpasswd → `mcp-status` on `:8781`). Uptime + `NRestarts` first; restart loops pulse. Snapshot fallback still written by watchdog.
- **P3 — Per-server request/error counts** from the nginx access log (which already segments by path).

### Docs
- ✅ ~~P2 — No client quickstart.~~ **DONE** README explains internals but not "here's how to connect Grok/Claude/Open WebUI in 3 steps." → Add `docs/CLIENTS.md` with per-client setup (URL + client_id + secret, screenshots).
- **P3 — Architecture diagram** is ASCII; a rendered SVG would read better.
- ✅ ~~P3 — `migrate-unit-names.sh`~~ **DONE** is a one-shot historical script cluttering root → move to `docs/history/` or delete after a grace period (archive-over-delete).

### Engine (`mcp-openapi-proxy`)
- **P1 — `API_AUTH_TYPE=Api-Key` bug.** Case-insensitive `api-key` match strips the scheme prefix → getzep needs an `EXTRA_HEADERS` workaround. Fix exists on branch `fix/api-auth-type-custom-scheme` (`5c8ae2d`) but isn't released; bridges run the **published** `uvx` package. → Merge + release, then drop the getzep workaround.
- ✅ ~~P2 — Pin the engine version.~~ **DONE** Bridges run `uvx mcp-openapi-proxy` (floating latest) — a bad release breaks all 14 at once. → Pin a known-good version in the launcher.

### UI (webcam / dogcam viewer — the one real front-end)
- ✅ ~~P1 — dogcam mislabeled~~ **NOT A BUG (corrected).** Template already branches on `isDog = host.includes('dogcam')`; via the real `dogcam.example.com` URL it correctly shows "Dogcam Live Feed". The earlier 'mislabel' was a localhost-testing artifact (host had no 'dogcam').
- **P3 — Camera detection is hostname-only.** `isDog` falls back to the webcam default if accessed by IP/localhost (the `path.includes('Webcam22')` fallback never fires — path is always `/`). → Add a data-based signal (image filenames `10.0.0.22` vs `.21`) for robustness.
- **P2 — No error/empty state.** When the API is unreachable the grid spins on "Loading…" forever (~10-12s even when healthy). → Timeout → "couldn't reach camera service"; skeleton + progress.
- **P3 — First-paint latency** (~10-12s aggregating 947 KB `analysis.json` + SSE). → Server-side pre-aggregation or pagination.
